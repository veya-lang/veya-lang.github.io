Veya is a statically typed language that reads like Ruby and compiles to small native binaries. There's no garbage collector and no interpreter, and most types are inferred.

Read the guideStatus

Veya is said "VAY-ah".

struct Order
  getter item : String
  getter qty : Int
  getter price : Float
end

orders = [Order.new("tea", 2, 4.5), Order.new("cake", 1, 7.0),
          Order.new("tea", 3, 4.5)]

totals = orders.group_by(&.item)
  .transform_values { |os| os.sum { |o| o.qty * o.price } }
totals.sort_by { |item, total| -total }.each do |item, total|
  puts "#{item.ljust(6)} #{total.round(2)}"
end

tea    22.5
cake   7.0

What you get

Write Ruby-like code with blocks, structs, enums and string interpolation. The compiler checks the types and turns the program into a single executable.

Compiled ahead of time

Cranelift writes native code directly, and a C backend is there for optimized builds. A hello world is a 460 KB binary that needs nothing installed.

No garbage collector

Memory is reference counted, with most counts handled at compile time. Blocks passed to yield are inlined, and iterator chains become one loop.

Types you rarely write

Method parameters carry types, and everything else is inferred. nil is only allowed where the type says T?, so nil errors are caught at compile time.

Errors that help

Compile errors show your code with a plain-language label and a fix you can paste, plus "did you mean" suggestions.

Batteries for real programs

Files and processes, an OptionParser, an HTTP(S) client, a web framework with templates, SQLite, JSON, regexes, fibers and threads.

One tool

veya run, build, test, fmt, new, deps, a REPL and a language server for editors.

A quick look

Every snippet on this page compiles with today's compiler.

Nil safety

User? may be nil and User may not. &. and || work as in Ruby, and an unchecked call on a T? doesn't compile.

def city(user : User?) : String
  user&.address&.city || "unknown"
end

struct Address
  getter city : String
end

struct User
  getter name : String
  getter address : Address?
end

puts city(User.new("Ala", Address.new("Kraków")))
puts city(nil)

Enums with data

Pattern matching with case/in is exhaustive: if you leave out a variant, the program doesn't compile.

enum Shape
  Circle(r : Float)
  Rect(w : Float, h : Float)
end

def area(s : Shape) : Float
  case s
  in Circle(r:) then 3.14159 * r * r
  in Rect(w:, h:) then w * h
  end
end

shapes = [Shape::Circle(1.0), Shape::Rect(2.0, 3.0)]
p shapes.map { |s| area(s) }   # => [3.14159, 6.0]

Command-line tools

OptionParser parses the options, and files are read line by line. The result builds into a single binary you can copy anywhere.

verbose = false
files = OptionParser.parse(ARGV) do |o|
  o.banner = "usage: count [-v] FILE..."
  o.on("-v", "--verbose", "Say more") { verbose = true }
end
files.each do |f|
  lines = 0
  File.each_line(f) { lines += 1 }
  puts verbose ? "#{f}: #{lines} lines" : lines.to_s
end

Web apps

Web::App gives you routes, forms and JSON, with ECR templates compiled into the program. Each connection runs in its own fiber.

app = Web::App.new
app.get "/hello/:name" do |c|
  c.html "<h1>Hello, #{HTML.escape(c.params["name"])}!</h1>"
end
app.get "/api/time" do |c|
  c.json %({"now": #{Time.now.to_i}})
end

Fibers and channels

Fibers are lightweight, and while one waits on a socket the others keep running. For CPU-bound work there are OS threads that share nothing.

results = Channel(String).new
["a", "b", "c"].each do |name|
  spawn do
    sleep 0.01
    results.send("#{name} done")
  end
end
3.times { puts results.receive }

Calling C

A lib block declares C functions. Both backends call them directly, with no wrapper code.

@[Link("z")]
lib LibZ
  fun crc32(crc : UInt64, buf : String, len : UInt32) : UInt64
end

puts LibZ.crc32(0, "hello world", 11)

Status

Veya 0.1 is a preview. The language, the compiler and the standard library are moving quickly, and there are no releases or installers yet. It's developed and tested on macOS (arm64). Linux is supported in the code but not tested yet.

Done: the language core, FFI, packages, a test runner, tools for command-line programs, and web apps. Next: desktop apps through C GUI libraries, then a first release.
